发布

为每个事件选定一条主张（允许彼此矛盾的主张并存，但发布只能各选一条）。 粗精度日期按覆盖区间计算；只有全部事件都能在区间内取到满足严格先后关系的具体日期，才会生成不可变新版本。 校验失败或版本冲突时，上一版本保持不变。

预约未来时刻（UTC）自动发布

选定主张后可指定一个未来 UTC 时刻预约发布。建立预约时即冻结事件、所选主张、 「先于」关系、求解日期与当前最新版本号；此后修改草稿或恢复草稿都不改变预约内容。 到期前访客只见旧版；到期时若冻结的基准版本号仍是当前最新版本号，才生成不可变新版本， 否则预约标记为冲突并保留内容供查看（不自动改基准）。

导入采访整理包（JSON）

上传或粘贴整理包：含批次标识 batchId、以包内唯一键 key 标记的事件 （每事件多条含出处的时间主张），以及按键引用事件的「先于」关系。 先只读预览待写入内容与数量；键重复、关系引用缺失、日期或出处非法会列出全部问题并整包拒绝。 确认须提交原包、预览返回的内容指纹与草稿修订号；内容被替换、草稿已变化或批次曾成功导入都会冲突且不写入。 导入只追加到草稿区（既有草稿、历史快照与访客年表不受影响），仍需选定主张、校验后发布才会公开。

并行编辑会话（两人同时整理：暂存 → 三方合并提交）

两名编辑者并行整理草稿时，各自开启编辑会话：开启时记录当时的草稿修订号与事件 / 时间主张 / 「先于」关系快照（基线，只读；草稿不加锁，对方可继续编辑）。会话内的修改先暂存为一批操作 （不直接写草稿）；提交时对照会话基线与当前草稿做三方合并：彼此未触及的对象或字段自动合并； 同一字段被双方改成不同值、编辑与删除相撞、关系端点已删除时整次拒绝，逐项列出基线 / 当前值 / 拟提交值 供人工重编，不覆盖另一人的改动。成功提交原子应用全部变更并返回新草稿修订号与临时编号 → 正式编号映射； 重试同一提交不会重复写入；冲突后请基于最新草稿重开会话。会话内容仅持编辑口令者可见，访客不可见。

按出处原文撤回公开展示（出处遮盖）

输入非空的出处文本先只读预览：系统会去除它与库存出处的首尾空白后再比较 （手工录入、整包导入、并行会话保存的出处可能带首尾空白；仅首尾空白不同视为同一出处， 内部空白与其他文字仍须逐字相同，部分包含不命中）。预览列出它在 全部已发布版本的事件主张与「先于」关系中命中的位置与数量（命中处显示库存原文），再携预览时的最新版本号确认。 确认后不改写历史快照或草稿：访客读取最新年表、任一历史版本、专题路线与勘误附记时，命中位置的出处统一显示 「出处已遮盖」，其余字段与版本号不变；以后发布（含预约发布、恢复后再发布）含同一文本或首尾空白变体的版本也自动遮盖。 持口令在版本详情与恢复草稿中仍可查看、使用原文。预览后若已发布新版本，确认会报冲突且不落库。

勘误附记（对指定已发布版本的事件 / 「先于」关系）

对某已发布版本中的事件或「先于」关系登记勘误附记（说明 + 出处）。附记只属于目标版： 不随草稿恢复或以后发布的版本继承；原快照、求解日期与草稿均不改动。同一目标只展示最新生效附记； 替代时系统自动提交你所见的附记号，两人同时替代仅一人成功（冲突方会看到当前生效附记，可再决定）， 旧附记全部保留供追溯。目标版已撤回时不能登记；撤回后访客不再看到该版及其附记。 附记出处沿用「出处遮盖」规则：命中登记的文本对访客显示「出处已遮盖」，此处可查原文与替代链。
